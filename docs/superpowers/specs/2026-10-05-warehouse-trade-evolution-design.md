# 主仓库：按通讯条件进化

日期：2026-10-05。状态：用户已授权按方案开发；第三、第四世代实现及验证完成。验证记录见 ../../review/2026-10-05-trade-evolution.md。

## 1. 目标与范围

用户已确认接受按游戏的通讯进化条件更新个体数据，且操作只能在主仓库中进行。目标是得到可继续传送的合法进化个体，沿用现有深绿卡片、荧光绿高亮、中文名称和弹窗交互。

产品名称统一为「按通讯条件进化」，不用「真实交换」「通讯完成」。不运行 ROM、不连接模拟器、不制造另一位训练家、不写游戏存档、不修改图鉴。进化结果以后通过原有下载流程写入目标存档；图鉴登记沿用该流程。

首版范围是建议的明确开发边界：PK3、PK4 格式，第三世代红宝石／蓝宝石／绿宝石／火红／叶绿，第四世代钻石／珍珠／白金／心金／魂银。支持普通交换和携带道具交换进化。格式按个体 Context 判断，不按起源 Version 判断。

第一、第二世代及第五世代以后首版只查看资料，操作区显示「该格式的通讯条件进化尚未支持」。小嘴蜗与盖盖虫需要第五世代格式，首版不提供搭档选择，也不新增多记录事务。后续扩展必须独立确认交换经历、作品例外与双方事务规则。

## 2. 现有代码与复用边界

- MainActivity.ShowWarehouseDetail 读取 LoadWorking，并把 StoredPokemon 传给共用详情弹窗；来源详情没有 warehouseRecord。它是执行权限的现有边界。
- EvolutionGuideDialog 展示游戏选择器、家族节点和直接进化条件；增加可选仓库操作入口，保持来源页面只读。
- EvolutionGuide.Family、GuideEdge、Availability、IsInGame 提供基础规则、目标形态和作品存在性。只筛选实际个体的直接边，不从正在浏览的节点推导执行对象。
- LocalRepository.SaveWorking 会保存 invalid／stale 数据，不能直接当作进化成功条件。新增进化专用入口，在保存前进行严格校验。
- WarehouseDatabase.Update 已有单记录 SQLite 事务和 ID／Revision 条件，复用它；没有数据库迁移、新表或新依赖。
- 原始 payload 与 working payload 分离；本功能只修改 working，保持 ID、CreatedAt、ParentId 与 original 不变。

不能直接复用通用 ApplyEdit 的 Species 参数完成进化：该逻辑仅修改种类，不保证默认昵称、进化后特性和能力缓存同步。也不能调用自动合法化去修复来源、PID、训练家或相遇数据。

## 3. 入口和页面

主仓库 → 查看个体档案 → 进化与形态 → 当前个体的直接进化条件 → 按通讯条件进化。

不增加首页按钮、批量操作栏按钮或长按菜单项。通用详情的「选择／取消选择」主操作维持原用途。

操作区固定在当前个体下一阶段条件中，与家族资料浏览分开。浏览其他节点仍可查看规则，但不会出现对该节点执行的按钮。切换游戏会重新评估并清除旧预览。

资料选择器继续允许浏览所有作品；只有受支持格式且所选作品 Context 与个体 Context 完全相同，才允许执行。PK3 不能选择心金执行，PK4 即使起源是绿宝石，也可以按第四世代作品规则处理。支持查看作品不表示支持下载到该作品。

默认规则沿用 EvolutionGuide.DefaultGame：起源作品与当前 Context 相符时使用该作品，否则采用该 Context 的 ReferenceGame。规则栏写「按《作品》规则」，仓库不声称这是个体当前所在游戏。

火红／叶绿等作品的剧情进度、全国图鉴解锁不在仓库个体中。本功能只核对个体条件和进化规则，不判断剧情解锁。条件区常驻说明「按个体条件处理，不检查游戏剧情进度」。不冒充完整游戏进化模拟。

## 4. 条件判定

先检查记录存在、可读且 Revision 未过期，再判断：

1. 类型是 PK3 或 PK4，且选定作品属于首版名单、Context 匹配。
2. 当前个体不是蛋；Species／Form 有效；来源和目标在所选作品中可用。
3. 源个体完整 LegalityAnalysis.Valid 为 true。不合法或无法校验时显示「当前个体尚未通过合法性检查，请先使用编辑／合法化更新」。本流程不自动修复。
4. 从当前 Species＋Form 的直接边中筛选 Trade／TradeHeldItem。不存在则无执行按钮；只有其他进化方式时继续展示资料。
5. TradeHeldItem 要求 HeldItem 等于规则 Argument，使用作品对应道具名称。缺少或错误时显示「需要携带 ××；当前携带 ××」。不自动发放／装备道具，不打开背包。
6. 不变之石阻止进化的规则按作品处理，不能全世代统一。首版第三世代阻止勇基拉进化；第四世代勇基拉例外，携带不变之石仍可进化且不消耗它。其他普通交换进化携带不变之石时阻止。
7. 若来源节点有多个道具分支，各分支分别判定。珍珠贝只允许执行当前携带道具对应的分支；缺少道具时列出两项要求，不擅自选择结果。

EvolutionMethod.Check 检查的是合法性历史，不直接用于当前触发条件。基础边之外的作品例外放在进化执行器中最小的明确分支，不能靠中文条件字符串匹配。

状态：可处理／条件未满足／格式未支持／规则不可用／个体不合法。未满足时可阅读原因但按钮禁用；核心接口重复全部检查，不依赖 UI 禁用保证正确性。

## 5. 预览与确认

点击可执行分支后异步生成克隆预览，期间按钮显示「正在检查…」。预览不写数据库，取消与返回不修改任何数据。

确认弹窗沿用现有 #0F201C 背景、#315249 描边、16dp 圆角；标题和箭头为 #D6FF63，正文 #E9F4EF，辅助信息 #91AAA1。主按钮沿用 primary_button，取消沿用现有次按钮。所有新交互触点至少 48dp，头像具有中文无障碍描述。

布局：

1. 标题「按通讯条件进化」。
2. 前后头像＋中文种类／形态名称；窄屏、大字体自动纵排。
3. 「按《作品》规则」与条件摘要。
4. 字段差异：种类、形态、特性、默认昵称、携带道具。仅展示实际变化。
5. 「等级、个体值、性格和闪光等个体信息保留」。
6. 「仅更新主仓库当前个体；不执行游戏通讯」。
7. 通过校验提示与「取消／确认进化」。

只消费规则要求的进化道具。普通 Trade 保留原携带物；勇基拉例外保留不变之石。不能把全部道具清空。

首版不自动学习进化招式：保留四个招式、PP、PP Up 与顺序，等价于跳过可选学招。确认区注明「保留现有招式，进化后可在详情中调整」。不引入额外学招向导，不静默覆盖招式。

## 6. 字段更新契约

在 source.Clone() 上处理，原对象不变。

允许变化：Species、规则决定的 Form、对应特性、非自定义的默认种类昵称、消耗的 HeldItem、依新种族值重算的战斗能力缓存，以及序列化要求的校验和。

必须保持：PID／加密常数、训练家姓名与 TID／SID、起源作品、相遇地点／等级／日期、语言、球种、性别、性格、闪光状态、IV／EV、经验值、等级、亲密度、感染状态、状态异常、缎带、标记、四招及 PP／PP Up；自定义昵称原字节内容保持。该操作没有交换双方训练家，所以不重置亲密度，不伪造交换地点或经手训练家。

特性处理使用原有效槽位及当前格式规则映射到目标种类，复用 RefreshAbility；PK3／PK4 的槽位与 PID 关联必须保持，不为了通过校验重掷 PID。如果目标不能以原槽位合法保存，预览失败，说明原因。

默认昵称调用本地 PKHeX 的 ClearNickname，使用个体语言和格式的命名规则，不用界面中文强行写入其他语言个体。自定义昵称不改。

经验值原值保留，重算后等级必须相同；若不相同则阻止，不能静默调整经验。

重算能力缓存时不能直接使用会清除状态／回血的 ResetPartyStats。保存前后保留 Status_Condition，若源有有效能力缓存，以新最大 HP 增量调整当前 HP、上限裁剪且 0 HP 保持 0；不凭进化治愈异常。无有效缓存时重新建立一致缓存并在差异中说明当前 HP 重算。核心验证中覆盖濒死与异常状态。

前后必须保持合法；序列化到仓库实际使用的 party payload 后再解析，再次校验，并核对保留字段。不能仅验证内存里的克隆。

## 7. 保存、并发与反馈

核心拟增加 TradeEvolution.cs，提供 Evaluate(source, game) 和 Preview(source, game, target)；结果是具体分支、是否可执行、中文原因及候选 PKM。输入 target 只能选 Evaluate 返回的边，不能把任意 Species 当目标。

LocalRepository 增加 ApplyTradeEvolution(stored, game, target) 专用入口：从仓库重新 LoadWorking → 重新评估 → 生成并序列化／回读校验 → 用现有 Update 事务保存。UI 不传任意已编辑 PKM 给此入口。提交依赖 stored.Revision，变更冲突导致整个提交失败，不覆盖新数据。

预览基于记录 ID＋Revision＋作品＋目标分支。确认时上述任一项变化均拒绝旧预览，要求重新打开。原始数据不会被更新。

保存期间复用 MainActivity 的 operationBusy，禁止重复点击及编辑、放生、上传／下载等竞争操作。提交中的弹窗不允许取消；Android 生命周期恢复时从仓库读取最终状态，不依赖预览对象判断成功。

成功：Revision 加一，Species 与 working 一致、LegalityStatus 为 valid；刷新仓库名称／头像／过滤／分页与选择状态，保留有效选择，关闭旧资料与预览，打开更新后的个体详情，Toast「已进化为××」。清除该个体的旧传送适配与目标槽位缓存，下载必须重新评估。

不播放传送隧道动画。沿用短暂按钮忙碌提示即可。

失败：取消、规则不匹配、校验失败、Revision 冲突或数据库写入失败均不修改记录。明确区分「进化未完成」和「进化已保存，但清单刷新失败，请刷新重试」，避免刷新失败后重复提交。数据库提交前异常回滚；提交后 UI 异常不宣称回滚。

恢复沿用已有「恢复原始」能力；它恢复首次导入版本，不是进化前一刻的工作副本。确认区如提供恢复提示必须注明这一点；首版不新增撤销历史或恢复按钮。

## 8. 修改文件与实现顺序

1. 新增 Core/Pokemon/TradeEvolution.cs：规则判定、克隆转换、差异和字段保留校验。
2. Repository/LocalRepository.cs：受控提交入口，复用现有 EntityBytes 与 Update，不改变通用 SaveWorking 的行为。
3. Android/EvolutionGuideDialog.cs：可选仓库执行回调、操作卡片与受控分支；只读调用默认无回调。
4. Android/MainActivity.cs：用 warehouseRecord 传入能力、确认弹窗、忙碌状态、刷新；如主文件新增量明显，弹窗逻辑放 MainActivity.TradeEvolution.cs，沿用已有 partial 模式。
5. Verifier/TradeEvolutionChecks.cs 与 Program.cs：接入现有 assert 检查，增加独立 --trade-evolution 模式；不引入测试框架。

先完成核心及验证，再连接 UI，最后模拟器检查。现有 EvolutionGuide 的查询不改成有副作用接口，现有传送引擎不改写进化规则。

## 9. 可执行验收

复用现有 Verifier 与合法测试个体，命令约定为 dotnet run --project src/MonoHome.Verifier -- --trade-evolution。测试输入由现有测试存档和固定合法样本提供，不联网、不下载 ROM。

核心与持久化必须覆盖：

- PK3／PK4 勇基拉等普通 Trade，合法来源进化为合法目标。
- 第三世代不变之石阻止，第四世代勇基拉例外允许且道具保留；鬼斯通携带不变之石阻止。
- 至少一只 TradeHeldItem 的正确道具消费、错误道具与无道具拒绝。
- 珍珠贝两种道具对应两种不同目标，不任意跳分支。
- 多阶段个体一次只处理直接下一步；多边相同结果去重，非 Trade 不可执行。
- 蛋、不合法来源、不支持格式、跨 Context 作品、任意目标和不可用分支拒绝。
- 默认昵称与自定义昵称、特性变化、PID／闪光／性别／经验／IV／EV／训练家／来源／招式保持；异常与濒死状态保持。
- 实际 payload 回读合法；成功 ID 不变、Revision 仅加一、数量不变、original 字节不变；失败 working 与 Revision 完全不变。
- 预览后编辑／放生导致冲突，不覆盖或复活记录；取消预览无写入。
- 更新后的个体重新走现有传送评估，不能复用旧适配数据。

UI 手动检查：来源页不能执行，主仓库可执行；跨世代只读；禁用原因可读；分支清晰；确认显示道具消费；双击只提交一次；返回无修改；成功头像／筛选／详情同步；错误不误报成功；窄屏与大字体可滚动、按钮可达；中文无障碍描述完整。

Release 构建要求 0 警告、0 错误；完整现有 Verifier 通过，确保传送、仓库编辑和放生无回归。验收记录写明实测支持作品／格式，不能把资料支持范围作为可执行范围。

## 10. 规则依据和开发就绪标准

主依据为当前仓库引用的本地 PKHeX EvolutionTree／EvolutionType／个人数据／昵称和合法性代码。不变之石例外参考 https://bulbapedia.bulbagarden.net/wiki/Trade_evolution 和 https://bulbapedia.bulbagarden.net/wiki/Kadabra_(Pok%C3%A9mon)，核对日期 2026-10-05。亲密度保留是本功能只执行进化编辑的明确产品规则，不宣称模拟完整交换副作用。

设计已明确可执行范围、入口权限、作品语义、规则过滤、字段允许变化／保留、序列化合法性、提交并发、缓存刷新、失败回滚与验收。没有需要实现者自行猜测的搭档事务或后世代交换身份字段。用户认可首版范围与交互后，可以据此编写实施计划并开发。

实现已通过合法样本、真实数据库事务、传送回归及隔离 Android 包验收。若保留字段要求与 PKHeX 校验不兼容，该个体应明确拒绝，不以自动修复悄悄改变契约。
