# 进化与形态：开发设计

日期：2026-10-04。状态：设计细化完成，待用户审阅；尚未实现。

## 目标与已确认约束

在宝可梦个体信息中增加「进化与形态」，展示完整进化家族、等级与条件、Mega、极巨化／超极巨化、太晶化及其他相关形态。用户只查看资料，实际进化在游戏中完成。沿用现有详情页的深绿卡片、荧光绿高亮、中文名称和弹窗交互。

## 方案选择

1. 全部放入详情页：入口直接，但分支和形态会挤占招式、能力数据的位置。
2. 详情摘要卡片 + 专用资料弹窗（采用）：详情保持紧凑，完整家族在弹窗中展开；沿用已有招式说明的操作习惯。
3. 独立图鉴主页面：本次不采用，会扩展导航与收集系统，超出当前个体指引需求。

## 入口与页面

来源存档与主仓库共用同一入口。在基础信息下方、招式上方增加摘要卡片：标题「进化与形态」、当前种类到下一阶段的头像与名称、下一步条件，以及「查看全部」。最终阶段显示「已到当前游戏的最终进化阶段」；无进化家族的种类显示「无普通进化」，仍可进入形态资料。

详情摘要默认仅展示当前个体所在路径及直接下一阶段；多分支显示下一阶段数量与一个可读摘要，不塞满所有分支。完整资料弹窗默认展开完整家族。

弹窗自上而下：

1. 标题「进化与形态」，当前个体名称与头像。
2. 游戏规则选择器；显示「当前存档」或「来源游戏／参考」，避免混淆。
3. 完整进化家族。
4. 当前个体的下一步条件。
5. 所选种类的特殊变化与其他形态。
6. 折叠的资料来源说明。
7. 固定底部「关闭」。返回键关闭弹窗并保留原详情页。

点击家族节点：在同一弹窗选中节点，更新条件与形态资料，不递归打开个体详情。当前个体始终用荧光绿描边与「当前个体」标记；浏览节点增加「正在查看」文本，不能覆盖当前个体标记。切换游戏保留当前浏览种类；若该形态不在作品中出现，说明原因。

点击条件摘要：在原位置展开完整条件，不新开一层弹窗。所有点击目标至少 48dp，节点和图标具备中文无障碍描述。

## 完整家族与布局

家族节点以种类 ID + 形态 ID 区分，边记录来源、目标、具体游戏、触发方式、条件与资料来源。常规单路径最多三阶段横排；窄屏／大字体自动纵排；多分支按来源节点纵向展开。完整家族包含前置阶段、后续阶段、旁系分支及相关地区形态，不能只从当前节点向后查询。

繁殖获得的幼年阶段可以展示，但必须标注「繁殖获得」，不能用进化箭头表示逆向进化。地区形态独立标注，不能把地区版本看成随意可切换的普通形态。

家族汇总使用本地 PKHeX 所支持各作品的进化连接去重，保留所有游戏差异。不能用单一最新游戏的树替代全家族，也不能合并掉不同形态或不同条件的边。所选游戏不支持的分支保留可读外观并标注「本作不可用」；资料尚未核实显示「条件资料未核实」，与不可用分开。

## 游戏选择与条件规则

存档页使用实际打开的 SaveFile 游戏版本与上下文，不能用个体 Version 代替：Version 记录的是起源游戏，可能不同于当前存档。主仓库采用可确定的来源存档游戏；仅有个体起源信息时标注「来源游戏／参考」，不声称这是当前所在游戏。

游戏选择器列出本地资料支持的具体作品及适用范围，不仅是世代。支持查看其他作品的条件，不代表 App 支持将个体传送到该作品。切换规则不转换、不修改宝可梦数据。

PKHeX EvolutionTree / Forward / Reverse 用于基础关系和条件参数；游戏差异另用小型本地资料表校正：作品缺少的地点、方法替换、版本／DLC限制、特殊机制与形态条件。每条补充条件记录具体作品、来源 URL 和核对日期。

EvolutionMethod.Check 是合法性历史检查，不能直接拿其结果当作「现在可以进化」。本功能单独读取当前个体能确认的字段，并展示尚需完成的触发动作。

条件逐条展示：等级、性别、亲密度／美丽度、持有道具、招式、同行宝可梦、时段、地点、天气、交换、步数、战斗行为等。需要参数的条件必须显示中文参数名，不能只展示「使用道具」或内部枚举编号。

状态统一为：

- 已满足：当前个体的数据能证明该项条件满足。
- 尚未满足：当前个体的数据能证明该项未满足，并显示当前值／要求值。
- 需在游戏中确认：时间、地点、背包物品、同行队伍、未被个体数据可靠记录的行为等。
- 本作不可用：资料已确定所选游戏不支持。
- 资料未核实：证据不足，不能给可执行指引。

仅当前个体的直接下一阶段进行个体判断；浏览其他阶段时展示种类规则，并说明「以下为该种类的进化条件」，不能拿当前个体数值替后续阶段判定。

等级达到要求仍显示「升级后触发」而非「已进化」。蛋显示「孵化后再按以下条件培养」；等级 100 的升级限制、可替代触发方式按作品判断。不要把所有条件压成一个绿色「可进化」。

## 特殊变化

特殊变化位于完整家族下面，不接在普通进化箭头后；按所选浏览节点展示，并可查看家族其他节点的变化。

### Mega 进化

列出具体作品中存在的 Mega 形态、X／Y 等分支与准确触发要求。展示变化前后属性、特性（作品确有特性机制时）和基础能力值；不能把基础能力值当作当前个体的实际战斗能力值。作品的条件差异和特殊例外独立处理，不能一律套用持有 Mega 石。旧游戏仍能查看跨作品资料，但明确「本作不可用」。

### 极巨化与超极巨化

分开说明极巨化机制和具有专属外观的超极巨化。种类支持、当前形态支持和个体极巨化标记是三个判断；IGigantamaxReadOnly 的字段只在相应格式中读取。旧格式没有字段时显示「当前格式无此数据」，不能当作未拥有资格。Gigantamax.CanToggle 描述极巨汤资格，不能单独当作完整的机制可用性判断。

显示相关道具／地点限制、超极巨化获取条件与专属招式说明；作品不支持则展示跨作品参考。

### 太晶化

采用正式中文名称「太晶化」。支持 ITeraTypeReadOnly 的个体读取有效太晶属性，不猜测；旧格式显示「当前格式无太晶属性数据」。展示所选作品的触发条件、属性效果及种类／形态特殊限制。太晶化通常是机制效果，不虚构为每个种类的一条独立进化分支。

### 其他形态

原始回归及相关种类的道具、特性、战斗、融合等形态进入本区。区分「可切换」「战斗中变化」「由地区／获取方式决定」；不同类别不能统一为使用道具。按所选作品列出有依据的条件；无相关形态时显示一条简短说明。

## 风格与素材

沿用现有色值：弹窗 #0F201C、卡片 #12201F、边框 #315249；主文字 #E9F4EF、次级 #91AAA1；强调 #D6FF63、条件 #8DE4D1。圆角、间距、标题大小与现有详情卡片一致，不引入新主题或图表库。

普通种类沿用已有图片与闪光状态；蛋的家族节点使用种类图片而非每个节点都显示蛋，当前个体头部保留蛋状态。特殊形态图片按种类 + 形态 + 闪光准确匹配；缺少时用中性占位与形态名称，不回退到普通图片冒充。素材来源和再分发条件必须明确，未验证素材不下载入库；当前发布可以使用如实标记的占位。

## 实现边界

- Core 新增 EvolutionGuide：构建家族、游戏差异和只读个体条件结果；不依赖 Android。
- 规则补充资料使用本地 JSON，只存 PKHeX 未覆盖的具体作品差异、特殊变化条件、来源和素材映射，不复制全部基础数据。
- Android 新增 EvolutionGuideDialog：完整弹窗；MainActivity 的公共详情方法增加摘要入口并传入当前存档规则上下文。
- PokemonSprite 增加显式形态查询；现有仓库和详情调用保持原行为，特殊形态缺图不能复用普通回退策略。
- Verifier 增加独立运行的 --evolution-guide-only 检查，不要求私有存档 fixture。
- 不修改 PKHeX 上游，不增加依赖，不改写个体、存档或传送流程。

整份方案包含完整能力；开发可分步完成，但只完成普通进化不能宣称整个功能完成。没有证据的资料是覆盖缺口，需要在验收记录中列明，不能用「本作不可用」掩盖。

## 开发顺序与验收

1. 核实所选作品数据，编写家族、作品差异和个体判断检查；先看到失败再实现。
2. 构建 Core 只读模型与补充资料。校验每种进化方法都有中文说明；有未知方法时检查失败或显式报告覆盖缺口。
3. 加入统一风格摘要和完整弹窗；在存档／主仓库两处验证上下文来源。
4. 接入全部特殊变化类别及形态资料，逐项核对条件与素材；验证种类资格和个体字段不能混用。
5. Release 严格编译、Verifier 检查、模拟器操作和截图核对；记录尚未核实的资料覆盖。

最小可重复验收用例：

- 小火龙三阶段、当前火恐龙高亮、Lv.36 条件与升级触发文案。
- 超音蝠／大嘴蝠家族完整，亲密度可读但不把历史合法性等同于当前进化资格。
- 伊布从任一进化后种类进入仍显示旁系分支；绿宝石与心金／魂银规则不同。
- 同一世代不同作品存在地点进化限制时，不只依据世代给出可执行指引。
- 交换携带道具、性别、招式、美丽度及地区形态能显示完整参数。
- 蛋、Lv.100、无进化种类、未来世代分支和资料缺口有明确状态。
- 喷火龙的 Mega 分支与超极巨化独立展示；切换作品不伪造当前个体资格。
- 盖欧卡／固拉多显示原始回归而非 Mega。
- 太晶属性读取有效值；旧格式、特殊种类与未支持作品都有准确说明。
- 专属形态缺图不显示普通图冒充；大字体、窄屏和多分支不裁剪。
- 打开／切换／关闭指引前后，个体原始字节及本地存档哈希一致。

## 资料依据与已查证代码

- PKHeX EvolutionTree 提供 Gen1 至 Gen9a 的树，粒度主要为上下文／世代；不是每款游戏的完整操作说明。
- EvolutionNetwork 的双向查询只保证当前路径的前后关系；完整旁系需要回到共同起点再遍历，并合并各上下文资料。
- EvolutionMethod.Check 含历史交换与合法性条件，不适合作为即时培养状态。
- FormInfo、FormConverter、IGigantamaxReadOnly、ITeraTypeReadOnly 可复用种类／形态与个体字段，具体作品触发条件需要资料校正。
- MainActivity 的来源存档和主仓库都调用 ShowPokemonDetailDialog，可复用同一入口。
- 当前 PokemonSprite 只接收种类、闪光、蛋；尚无准确的形态图片映射。
