# MONO / HOME：全世代中央仓库设计

## 目标

将应用从“绿宝石到心金的单一路线”改为本地中央仓库：任何 **PKHeX.Core 可识别的零售版存档格式** 都可以登记为来源或目标。用户可从任意来源存档选择宝可梦上传到仓库，再下载到任意已登记的目标存档。

所有数据仅存放在设备本地。来源存档和仓库原件永不被改写；只有经过目标格式和合法性校验的副本才可写入目标。

## 已确认规则

1. 不存在固定的“双向”或“世代路线”首页。所有已登记存档均可作为来源，也均可作为目标。
2. 首页明确展示“来源存档 → 上传实体卡片 → 中央仓库 → 目标存档”。来源与目标是两个独立选择项，目标不可等于来源。
3. 上传区不使用一行文本清单。每只可上传宝可梦使用与仓库相同的两列卡片：National Dex 图标、简体中文名、等级、闪光标识、携带道具摘要、队伍/盒子位置；点按选中，长按显示详情。
4. 中央仓库保存不可变原件、来源元数据和当前可管理副本；编辑只创建新的合法副本。
5. 下载时，系统生成面向目标存档的临时合法实体。目标不支持的物种、形态、道具、招式、球种、特性或状态必须以中文说明阻止写入，绝不写入非法数据。
6. 官方存在的前向转移可以采用保真规则；不具备官方路线的世代组合使用“目标世代合法副本”，并在详情中列出发生的变更。它不是伪装成官方传送的逆向实体。
7. 每次写入前创建私有恢复点，写后重新读取目标存档并逐只执行合法性校验。没有持久读写权限、目标被外部修改或校验失败时禁止写入。

## 交互与视觉

交互原型：[`docs/prototypes/universal-save-hub-prototype.html`](../prototypes/universal-save-hub-prototype.html)。原型是本设计的视觉与交互验收依据；它不读写真实存档。

### 首页

1. **存档页**：`导入存档` 打开通用文件选择器并自动识别游戏；已登记存档显示中文游戏名、世代、读写状态和“更新/重新授权”。用户先点选一个来源存档，再看到其队伍和盒子的宝可梦卡片；不再有“导入绿宝石”“导入心金”两个硬编码入口。
2. **上传操作**：来源卡片下方使用“单盒视图”，以横向标签切换“随身携带、仓库 1、仓库 2 …”，一次只展示一个分组。随身携带最多 6 格；每个仓库按实际 30 槽位渲染为与中央仓库一致的双列宽卡网格，空槽位显示为非交互占位，已占用槽位展示 National Dex 图标、中文名、等级与关键状态。当前盒子的 30 只通过自然纵向滚动浏览，不能为了在首屏塞下所有槽位而压扁实体卡片。这样不会把多个盒子的数百只宝可梦平铺成长列表。只有在来源卡片被选中后，页面底部才显示 `上传 N 只至中央仓库`；上传不显示、更不要求选择目标存档。
3. **中央仓库页**：保留卡片网格、选择、批量选择和长按次级操作。未选中实体时不显示下载按钮；选中后只显示 `下载至目标存档`，并在点击该按钮后才打开目标存档选择层。仓库卡片增加当前目标适配状态，但不把适配失败替代为编辑入口。
4. **下载操作**：目标选择层列出全部已登记且可写的存档。选定后显示“正在适配 / 可传送 / 不可传送（原因）”；主操作为 `适配并下载至 {目标游戏}`。仓库下载不依赖当前存档页曾选择的来源。
5. **传送动画**：上传动画仅表示“来源存档 → 中央仓库”，固定约 2 秒：已选宝可梦图标先收束进入精灵球，精灵球完成一次封装摇动后进入发光的本地传送隧道；阶段文案依次为“定位宝可梦 / 封装传送包 / 进入中央仓库”。下载动画仅表示“中央仓库 → 目标存档”。动画只表示本地事务进度，失败时实体留在来源或仓库，并显示失败原因。

### 次级能力

长按来源卡片提供“查看个体档案”“上传至中央仓库”；长按仓库卡片保留“个体档案、图鉴、编辑并另存合法副本”。传送记录和编辑表单不在主页显示。

## 核心数据与适配器

### 存档登记

`RegisteredSave` 记录 `SaveFile` 的准确游戏版本、世代、格式类型、快照哈希、可持久化 URI 权限和显示名称。登记服务不根据文件扩展名或固定请求码判断世代；以 `SaveUtil.GetSaveFile` 的实际解析结果为准。

### 通用目标适配

新增单一的目标适配服务，而不是为每两个游戏组合创建一个类。它接收仓库 PKM、来源元数据和目标 `SaveFile`，按以下顺序执行：

1. 检查目标游戏是否有该物种与所选形态。
2. 创建目标存档的空白 PKM 格式；在 PKHeX.Core 的目标版本数据中重建可接受的个体、训练家、等级、招式、特性、球种、道具与状态。
3. 对生成体执行 `LegalityAnalysis`，只接受 `Valid` 结果。
4. 产生 `TargetPreparation`：状态、中文原因、变化摘要、目标格式、待写入实体和缓存键。

缓存键为 `{仓库记录 ID, 修订号, 目标存档 ID, 目标快照哈希}`。任何编辑、目标更新或权限重授权都会使缓存失效。

适配器必须区分三种结果：

| 结果 | 行为 |
|---|---|
| 官方保真可用 | 保留来源关联字段，写入前仍验证 |
| 目标世代合法副本可用 | 重建必要字段并报告变化 |
| 无合法目标 | 禁用传送并展示确定的中文原因 |

“任意世代”表示所有可解析存档都可以被选作来源和目标；不意味着每只宝可梦都能在每个目标游戏存在。不存在于目标世代的物种或无法生成合法相遇的组合属于第三种结果。

### 写回事务

通用写回器接收一个目标 `SaveFile` 和准备好的目标实体集合，寻找空盒子槽位、写入临时文件、回读解析并逐只合法性校验。之后才使用 SAF 写入已登记 URI，更新本地快照和传送日志。批量操作是一个目标文件事务：其中一只失败，整个批次不写入。

## 分期与发布声明

该架构先替换硬编码 UI 和数据模型，再逐步实现各目标格式的合法重建。支持矩阵以“可导入”“可作目标”“可合法下载”“已用真实 fixture 回归”分别标注，禁止把“PKHeX 可解析”表述为“已完成任意路线转换”。

首个实现里必须同时覆盖当前绿宝石、心金、魂银真实存档，并将其余 PKHeX 可解析格式显示为“可登记，目标适配待验证”，直到各格式有对应的真实 fixture 和回归。这样先交付通用交互与安全边界，不把未经验证的世代写入伪装成可用功能。

## 验收

1. 导入任一支持格式后，应用自动显示游戏与世代；不再要求用户先选“绿宝石”或“心金”。
2. 来源和目标从同一份已登记存档列表选择，不能选同一存档作为两端。
3. 来源区每只宝可梦均以图标卡片展示，不出现一行文本 `Spinner` 列表；卡片信息至少包含中文名、等级、闪光、道具和队伍/盒子位置。
4. 存档页选中实体前没有目标选择或下载按钮；中央仓库未选中实体前没有目标选择或下载按钮。来源上传与仓库下载是两个独立的主操作。
5. 现有绿宝石、心金、魂银 fixture 允许上传至仓库；当前已验证目标路线继续能完成写回与回读合法性校验。
6. 对没有已验证适配器的目标，UI 明确显示“目标适配待验证”，禁用传送；不产生文件、不修改目标。
7. 对已验证目标，单只和批量下载都只能在写后回读、哈希校验、每只 `LegalityAnalysis.Valid` 后报告成功。
8. 仓库原件、来源存档在上传、编辑、适配失败和写回失败后哈希不变。

## 非目标

- 不宣称官方服务认可或线上可用。
- 不绕过 Android 的文件权限，亦不写入没有可验证读写权限的 URI。
- 不为了“任何组合都能下载”而生成非法实体。
- 不为未经真实存档回归的格式打开写入开关。
