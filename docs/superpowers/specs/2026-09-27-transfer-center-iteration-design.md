# MONO / HOME：传送中心迭代设计

## 1. 目的与结论

本迭代将 MONO / HOME 从“存档编辑器式的导出工具”调整为本地宝可梦传送中心。

保留现有 .NET for Android 与 PKHeX.Core。Android UI、文件选择、写入和动画继续使用原生 Android API；不在本迭代改写为 Kotlin，也不重写 PKHeX 的存档、转换或合法性规则。

产品主流程只有：**中央仓库选择宝可梦 → 选择已登记目标存档 → 自动适配 → 传送至目标存档**。

## 2. 已确认的产品规则

1. 来源存档与仓库原件永不被传送或编辑流程改写。
2. 首页不展示编辑表单、传送记录、转换差异确认或“导出副本”流程。
3. 编辑是次级管理能力：长按仓库卡片进入，保存时只生成新的合法仓库副本。
4. 图鉴与编辑同为次级能力；既可独立浏览，也可从仓库实体跳转至对应种类。
5. 选定目标后，仓库实体自动预检并生成目标适配版本；适配不覆盖仓库原件。
6. 用户触发的是“传送至目标存档”，不是“生成转换文件”。
7. 目标存档没有可靠持久写权限时，传送被阻止并要求重新授权；不再把导出新文件作为主流程回退。
8. 内部恢复点、临时文件、重新读取与哈希校验保留为后台安全机制，不作为主页交互。
9. 首个完整发布路线仍是 Emerald → HeartGold / SoulSilver；其他路线仅可浏览资料，不得伪装为可传送。

## 3. 信息架构

### 3.1 首页：传送中心

首页按以下顺序呈现：

1. 已登记存档状态（含目标可写性）。
2. 中央仓库卡片网格。
3. 当前目标存档选择器。
4. 选中实体的传送操作栏。

仓库卡片使用 PKHeX 简体中文种类名和 National Dex 图标，只展示传送有关的摘要：等级、闪光、道具、蛋、异常状态与当前目标适配状态。点按用于单选/多选；长按打开次级操作菜单。

主操作栏只保留一个强操作：`传送至 {目标存档名称}`。无选中实体时不显示。目标未就绪时显示原因及“重新授权目标存档”。

### 3.2 长按菜单与次级页面

长按仓库卡片显示：

- 查看个体档案
- 查看宝可梦图鉴
- 编辑并另存为合法副本

“个体档案”是只读信息页，展示该仓库实体的来源、训练家、PID、等级、招式、状态和历史；不会成为首页内容。

“编辑并另存为合法副本”进入独立编辑页。编辑页保留现有字段：种类、昵称、等级、性格、特性、性别、形态、闪光、蛋、携带道具、状态、宝可病毒、招式、IV、EV、丝带和标记。唯一保存动作是 `生成新的合法副本并保存至仓库`。

“查看宝可梦图鉴”可由顶部更多入口独立打开，也可从长按菜单直达指定种类。

### 3.3 图鉴

图鉴数据全部离线读取 PKHeX 的物种、招式和世代数据。条目使用简体中文名称并提供中文名称/全国图鉴编号检索。

每个条目分为：

- 种族资料：属性、特性、种族值、性别比例、孵化组、成长速度、形态、进化链。
- 世代资料：指定游戏中的存在性、形态支持、可用特性与合法学习方式。
- 当前仓库实体：该实体与种族资料相关的个体状态。
- 传送评估：对当前目标显示可传送、正在适配或不可传送及原因。

未发布传送路线的游戏仅显示资料，不显示可传送按钮。

## 4. 仓库与适配数据模型

每个仓库实体由三个不可混淆的层组成：

| 层 | 用途 | 可变性 |
|---|---|---|
| 原件 | 上传时的原始 PKM 和来源快照 | 永不变更 |
| 仓库副本 | 当前实体的合法可管理版本 | 编辑时仅通过“另存副本”产生新实体 |
| 目标适配 | 以仓库副本和目标存档生成的临时目标版本 | 仅限该目标与该传送事务 |

目标适配按 `{仓库实体 ID, 目标存档 ID, 工作副本版本}` 缓存。编辑产生新实体或目标存档外部变更时，旧适配缓存失效。适配结果至少包含：状态、失败原因、变化摘要、目标格式、目标合法性结果和生成时间。

适配逻辑延续现有 `ConversionProfile` 与 PKHeX.Core 校验。合法转换可重建目标世代必要字段；保真路线仅在来源与目标规则均成立时通过。当前 UI 不把“保真/合法转换”作为主流程选择，路线能力由 Profile 与实体状态决定；详情页可说明实际采用的规则。

## 5. 编辑并另存合法副本

编辑页从仓库副本复制到内存草稿，不直接写原实体。保存时：

1. 校验输入范围。
2. 按来源上下文生成或修复可成立的合法实体。
3. 对无法由规则引擎生成的组合返回明确错误，不保存伪合法数据。
4. 将通过验证的实体作为新的仓库记录保存，保留父实体 ID 与编辑来源信息。
5. 新记录的目标适配状态为“待适配”。

编辑页可跳转图鉴查询种类、特性、招式、形态及对应目标游戏兼容性。

## 6. 直接传送事务

导入目标存档时必须请求并持久化读写 URI 权限。目标状态分为：可读取、可传送、需重新授权、外部已修改、不可用。

一次传送事务：

1. 验证目标状态为“可传送”，并验证仓库副本与目标适配结果未过期。
2. 若未适配，后台生成并校验目标适配版本。
3. 在应用私有目录创建恢复点，并保存目标文件的哈希。
4. 在临时目标存档中插入一个或多个适配实体。
5. 重新解析临时文件，逐实体执行合法性检查。
6. 以可验证方式写回已登记目标 URI。
7. 重新读取目标 URI，验证字节、格式和插槽结果。
8. 原子更新目标本地快照、仓库传送状态与本地传送日志。

任一失败不得变更仓库原件或仓库副本。写回前失败删除临时输出；写回后重新读取失败时保留恢复点并将目标标记为“需要恢复”。恢复点只在目标存档管理页中提供，不在首页展示。

对于不支持稳定写回的 URI，首页不生成导出文件，不显示传送按钮，改为“重新授权目标存档”。模拟器存档位于 Android 受限目录而无法使用 SAF 时，产品提供一次性迁移/重新定位指引，但不绕过 Android 存储限制。

## 7. 实施切分

### 阶段 A：传送主流程

- 删除主页上的编辑表单、导出副本和差异确认入口。
- 导入目标时申请持久读写权限并记录可写性。
- 将现有 `OverwriteRegisteredHeartGoldAsync` 整合为已验证的主事务，而非隐藏死代码。
- 将单只与批量传送改成“适配 → 直接写回 → 校验 → 完成”。
- 扩展 Verifier 覆盖目标写回、回读与失败恢复。

### 阶段 B：仓库管理与编辑副本

- 增加卡片长按菜单、个体档案页和独立编辑页。
- 将现有原地工作副本编辑改为创建新仓库实体。
- 实现父子关系、编辑来源与适配缓存失效。

### 阶段 C：图鉴

- 实现全国图鉴浏览、中文搜索和种族资料页。
- 接入按目标游戏显示的特性、招式、形态和传送评估。
- 在编辑页提供到相应图鉴条目的上下文跳转。

### 阶段 D：路线扩展

- 每增加一条 `ConversionProfile`，必须同时增加真实存档 fixture、逐只转换回归、批量写回回归与 UI 目标适配回归。
- 不以“支持 Gen I–IX”作为发布声明；支持矩阵是唯一可传送范围的依据。

## 8. 验收标准

1. 首页不含编辑字段、传送记录、导出副本或差异确认入口。
2. 在已登记且可写的心金存档中，选择一只绿宝石仓库实体后可完成一次“传送至心金存档”；目标文件回读后包含该实体且合法。
3. 目标 URI 不可写、已失效或外部修改时，传送按钮不可用并给出中文原因；不创建导出副本。
4. 传送前后的仓库原件字节不变；仓库副本只在编辑时新增记录。
5. 编辑任意受支持字段后，只能通过“生成新的合法副本”保存；原记录保持不变，新记录经过合法性验证。
6. 长按卡片能进入个体档案、图鉴和编辑入口；正常点按不进入编辑。
7. 图鉴使用简体中文物种名，能查询仓库物种并显示当前目标游戏兼容性。
8. 传送写回失败时，应用保留恢复点并不丢失仓库数据；恢复点可在存档管理页找到。
9. 所有发布路线均由对应的核心与 Android UI 回归覆盖。

## 9. 非目标

- 本迭代不迁移到 Kotlin/Compose，不建立跨语言桥接层。
- 不重写 PKHeX.Core 规则。
- 不提供云同步、账户、联网交易或在线图鉴。
- 不在未验证路线中允许“强行传送”。
